StackEndBox Encrypted Backups

This is StackEndBox's owner-operated backup tool, not a public customer service. It exports the existing Supabase application's database and file storage, encrypts the exports and uploads them to the owner's private Google Drive folder.

The hosted job runs in a restricted GitHub Actions environment. It doesn't need the owner's computer to stay on. The initial Google authorization uses a local callback and Google's folder picker.

Google access is limited to drive.file, covering files selected for or created by this application. The application checks the authorized account and exact private backup folder before every backup. It doesn't request access to the entire Drive account.

Only the public encryption key goes to the hosted runner. The private recovery key and separate recovery code are required for recovery and aren't sent to GitHub Actions.

Operational terms

This tool is restricted to the authorized StackEndBox owner. It isn't offered for other accounts. It may create encrypted backup generations and move expired application-owned generations to recoverable Google Drive Trash according to the reviewed retention setting. It doesn't change sharing permissions or permanently empty Trash.

Scheduled execution can be delayed or disabled by the hosting provider. Check the newest verified backup and failure notifications regularly. A logical backup and isolated SQL recovery drill don't establish point-in-time recovery or a complete hosted Supabase disaster recovery.

Revoking the app's Google authorization stops future uploads. Backup recovery also requires independent account access, the encrypted portable key and the separately held recovery code.

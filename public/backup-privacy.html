StackEndBox Encrypted Backups privacy and data use

This notice describes the dedicated owner-operated backup integration, separately from StackEndBox's public website and client portal.

Google data and permissions

The app requests only Google's drive.file permission. It reads the account email to verify the authorized owner, checks the selected backup folder's metadata and permissions, and reads or manages the files selected for or created by the app. It creates encrypted backup files, downloads those files to verify integrity and may move older application-owned generations to recoverable Trash. It doesn't request access to all Google Drive files or change file-sharing permissions.

Credential and backup custody

The Google offline OAuth credentials are stored as encrypted secrets in the dedicated GitHub Actions backup environment, restricted to the protected production branch. They're used to request temporary access tokens for backup operations. They aren't placed in repository source, browser application bundles, generated public artifacts or intentional log output.

Database exports can include client records, authentication identities and password hashes, memberships, domain assignments, payments and support records. File-storage payloads are included when present. Backup content is encrypted before upload to private Google Drive. The recovery key and code are kept separately from the hosted job.

Use, providers and retention

Google account and Drive data are used only for this backup and recovery workflow, not for advertising, sale, model training or unrelated agency communications. The workflow uses Supabase for the source database and files, GitHub Actions for execution and encrypted secret storage, and Google Drive for encrypted offsite custody.

The reviewed retention setting keeps fourteen complete automated generations and at least two. Incomplete generations and the separately uploaded manual custody archive aren't retired automatically. Trash still consumes Drive space until the owner separately approves permanent removal.

Owner controls and recovery limits

The owner can revoke Google authorization through their Google account, disable the scheduled workflow, or remove private Drive files. Revocation doesn't delete existing backups. Encrypted backups require the portable private recovery key and the separately held recovery code to decrypt. Protecting and independently preserving those recovery materials remains necessary.
